## 確かめられたこと

**(1) 明細 → 塗装パネルの自動連動**: 取替(0)・修理(2)・板金(6) の行のうち 20.DB にあるパネルが、塗装タブを開いた時点で
`PaintingPanel` に起きる。区分は明細のまま引き継ぎ、塗装面積の既定は **1/2**。指数は塗装面積ごとに CHM の別の列
（取替 → 新品 / 1/1 → 1 / 1/2 → 2 / 1/3 → 3）を引く。

**(2) 並び順**: **連動した行（部品コード昇順）→ パネル追加した行（追加した順）→ 手入力の塗装行**。
パネル追加した 0800 は、部品コードでは 2 番目なのに**末尾**に入った。

**(3) 下処理面積 `PrepareArea`**: 再計算後の値は `round(切上(パネル面積 × 塗装割合) × 0.345)` で、
実機 3 例（94×1/3 → 11、94×1/2 → 16、28×1/1 → 10）がすべて式どおり。
**塗装面積を変えただけでは更新されず、古い値が残る**（A2 で 1/3 にしても 16 のまま、A13 の再計算で 11 になった）。
実案件でこの欄がばらつくのはこのため。金額に影響しない表示欄。

**(4) ADDATA との突き合わせ**（すべて一致）

|---|---|---|

**(5) 塗装計（A10 の画面と NEO）**

```
外板パネル 616,000（7.7）＊ ＋ 加算基礎 240,000（3.0）＊ ＋ ブース 40,000（0.5）
＋ バンパ 136,000（1.7）＋ 内板骨格 184,000（2.3）＋ 付加塗装 88,000（1.1）
= 塗装工賃計 1,304,000
材料代 14% → 182,560（＝ 1,304,000 × 0.14）
追加項目 40,000（0.5。塗装工賃計にも材料代にも入らない）
塗装費用計 1,526,560
```

**(6) 生成器との突き合わせ**: 同じ内容を `estimate.json` にして生成器に通したところ、
`PaintingTotal`（工賃計・材料代・塗装費用計）と `PaintingPlan`・`PaintingBumper`・`PaintingFrame`・`PaintingEtcetera`・
`PaintingOther` の値、塗装パネル 5 行の中身が**実機の NEO と一致**した（`gen_from_cogni_pnt.neo`）。
残る差は ①`SortNo`（コグニ内部の操作カウンタ。読込時に振り直される）②`PrepareArea`（実機側に古い値が残っている行）
③実機で手入力し直したボデーシーリングの印 `#` ④追加項目の行番号（実機 0 / 生成器 9。名称は同じ）だけで、
いずれも金額に影響しない。

**(7) この実験で直したこと**

- 塗装パネルの並びを「連動 → パネル追加 → 手入力の塗装行」にした（それまでは全部を部品コード昇順にしていた）
- 塗装工賃計の警告が、内板骨格塗装・ボデーシーリングを足す前の値で比べていた（誤警告）
- 追加項目を**指数だけ**で書いた見積で、印字の塗装工賃計（追加項目を含まない）と一致しないと判定していた
