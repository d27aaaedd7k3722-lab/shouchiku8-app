目的: 生成器が「推定」で書いている塗装パネル・標準指数・連動の規則を、人がコグニで作った NEO と全列比較して確かめる。

## 規則の精密化（Codex レビューで詰めた点）

- 規則 3（sub 不一致なら共通行へ逃げない）で、ボディ専用行が共通行を押しのけるのは **同じ年式群（grp）で、グレード/装備フラグにも合う** 行だけ。
  別年式群や装備不一致のボディ行があるだけで、今の年式群の有効な共通行を消してはいけない（過剰除外を防ぐ）
- `_select` 側の「ボディ専用行が sub 付きで全部不成立なら次の年式群へ」は必要な分岐。一度外すと fixture cogni_W90 が
  4800 の ChangeTotal 830,600 ≠ 実機 985,800 で落ちる（「全候補 sub 付きならそのまま採る」救済が sub=4801 行を採ってしまう）
- 規則 6（パネル追加 → `BaseWageByManual='*'`）を fixture で守るため、監査の比較除外から `BaseWageByManual` を外した。
  結果 H24（加算基礎を画面で直した実験）だけ 生成 '*' vs 実機 '' になるので既知差に登録（見積 3.1 ≠ 標準 3.0 → 生成器は '*'）。
  これで P1・W90（'*'）と他 66 本（''）が実際に比較される

## 操作上の注意（次に実機を触る人へ）

- `Windows 入力エクスペリエンス`（TextInputHost）と通知トースト（ShellExperienceHost）がコグニの前面判定を奪う。`Stop-Process` で再起動させてから `SetForegroundWindow`
- 基本単価の入力欄は既定の `0` が残るので、`ctrl+a` してから打つ（9700 → 97000 になった）
- 明細は 部品コード → Tab → 修理方法ボタン（0:取替 等）。複数品番があるとダイアログが出る
- 保存ダイアログのファイル名欄は既定名が残るので `ctrl+a` してからフルパスを打つ。存在しないフォルダは「パスが存在しません」
- 結果画面では基本単価を直せない

分かったこと（規則として採用。判断規則 10-18）:

1. **修理(2) は明細に入れただけで塗装パネルが 1/2 で自動連動する**（20.DB にあるパネルなら例外なし）。`PaintingLinkParts` に全行（`PaintingFlag 0`）、`AddedFrom 0`。生成器の `auto_panels` の既定を 1/1 → **1/2** に変更
2. 下処理面積 `PrepareArea`: 近似式（切上(面積 × 割合) × 0.345 四捨五入）が 81→14、88→15、40→7、68→12 で合い、**ルーフ 287 1/2 だけ実機 48 ≠ 式 50**（1/3 でも 32 ≠ 33）。J87 のルーフ 285 1/3 → 33 は式どおりなので、面積の大小ではなく車種（車形 6/7）か COM/T_KEI_4 の係数の差と推定。切上(面積×割合÷3) は W66 ルーフに合うが J87 45 1/1 → 16・285 1/3 → 33 が外れるので採らない。金額に影響しない表示列なので既知差 W66y として管理
3. 修理行（工賃未入力）の `ConstructGroup` は **11.DB の修理(S) 行**の値（4802 'Z0'。4600 は取替行 'M8' でも修理行 '  '）。`PartsPriceFlag` は標準品番 '-'（標準価格 0）でも **1**
4. 複数枚の連動減算・加算基礎の変化は生成器が元から一致（CHM の複数枚列）

残った差（状態依存・既知）: 明細画面から入れた行の `OrderFlag '0'`、`PaintingPanel.SortNo`、`TimeTotal` の float の癖、`pt_ExtraFlag`、車名末尾の全角空白、テンプレート由来の既定値。
