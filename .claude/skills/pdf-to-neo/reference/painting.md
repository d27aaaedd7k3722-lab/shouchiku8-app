# 塗装のすべて（コグニセブンの塗装画面 → NEO → reading.json）

塗装だけを 1 枚にまとめた正本。**転記で迷ったらここを見る**。根拠は ①コグニ実機の保存版 NEO（N-ONE J52・N-BOX J87・W66・W90 ほか）②実案件 NEO 700 本の統計（2026-09-20 に集計。金額・区分・フラグだけを読む）③ADDATA の表（20.DB / CHM / T_KEI_3 / BAN / NAIKOKUA / fukaetc / 2TONE）。
散らばっていた規則（判断規則 10-12 / 10-13 / 10-15 / 10-17 / 10-18 / 10-19 / 10-20 / 10-25 / 10-30）はここから引く。

## 1. コグニの塗装画面の構造（タブ）と NEO の表

| コグニの画面 | 何を入れる所か | NEO の表 | 生成器に渡すキー |
|---|---|---|---|
| **塗装条件** | 塗料・塗膜・高機能塗装・材料代割合・ブース・2トーン・低隠蔽性塗色・**入力方式（指数/実額/参考）** | `PaintingPlan` | `paint.paint` / `coat` / `hf` / `material_rate` / `material_round` / `booth` / `two_tone` / `input_type` |
| **外板パネル** | 塗る外板パネルの一覧（取替・修理・板金）と塗装面積 1/1・1/2・1/3、**行追加**（20.DB に無い部位の手入力） | `PaintingPanel` | `paint.panels[]`（`manual: true` が行追加） |
| （外板パネルの下） | **加算基礎数値**（枚数で決まる基礎指数）・**ブース加算** | `PaintingPlan.Base*` / `Booth*` | `paint.base` / `paint.booth` |
| **バンパ** | 前後バンパの塗装（新品・変形修正・外傷修正小/大 × 一色/二色 × 絞模様）と**バンパ加算基礎** | `PaintingBumper` / `PaintingPlan.BumperBase*` | `paint.bumper_front` / `bumper_rear` / `bumper_base` |
| **内板骨格** | ラジエータサポート・フロントピラー・センタピラー・リヤフロアの塗装 | `PaintingFrame` | `paint.frame`（下の §6） |
| **付加塗装** | ドアサッシュ黒塗り・ボデーストライプ・ボデーシーリング・防錆ワックス・低隠蔽性塗色・2コートソリッド・2トーン | `PaintingEtcetera` | `paint.door_sash` / `stripe` / `sealing` / `wax` / `low_cover` / `two_coat_solid` / `two_tone` |
| **追加項目** | 工程の手入力 10 行（内板調色・水性加算・ヒンジ塗装・チッピング・ホイルハウス・ホースメント・インナーパネル・フロア・アンダーコート・防錆処理） | `PaintingOther` | `paint.other[]` |
| **塗装計** | 区分ごとの工賃・材料代・小計・割合・**塗装費用計** | `PaintingTotal` / `Total.pn_*` | （計算結果） |

**合計の関係（判断規則 10-25）**

```
塗装工賃計 = 外板パネル + 加算基礎 + ブース + バンパ（+バンパ加算） + 内板骨格塗装 + 付加塗装
塗装材料代 = 塗装工賃計 × 材料代割合（端数処理は工場ごと。§7）
塗装費用計 = 塗装工賃計 + 塗装材料代 + 追加塗装費用計（= 追加項目の工賃）
```
- **追加項目（PaintingOther）は材料代の対象外**で、`PaintingTotal.WageTotal` にも入らない（`Total` にだけ足す）
- コグニ印刷の「塗装工賃計」は**内板骨格塗装を含み、追加項目を含まない**
- 実案件 585 本（入力方式 = 指数）すべてで `WageTotal + Other + Material = Total` が成立

## 2. 入力方式（指数 / 実額 / 参考）— `PaintingPlan.InputType`

実案件 NEO 700 本: **指数 585 本（84%）/ 実額 114 本（16%）/ 参考 1 本**。

| 方式 | InputType | どんな見積で使うか | NEO の姿 |
|---|---|---|---|
| **指数** | 1 | 塗装明細（パネル・加算基礎・バンパ…）が印字された見積 | パネルごとに指数・工賃、材料代は割合から計算 |
| **実額** | 0 | **「塗装費用 一式 ○○円」しか印字されていない見積**（ディーラー概算・輸入車・板金工場の概算） | パネル 0 枚（114 本中 76 本）、`WageTotal`・`MaterialTotal` は 0、**`TotalOutTax` に総額だけ**。加算基礎・ブースは無効（`BaseTime -1`・`BoothFlag 0`）、工賃計の手入力印も付かない |
| **参考** | 2 | 参考見積（1/700 本。計算は指数と同じで、位置づけだけが違う） | 指数と同じ。材料代は手入力（`MaterialTotalbyManual '*'`）のことが多い |

- reading に `"input_type": "実額"`（`"actual": true` でも可）と書くか、**塗装の内訳が 1 つも無ければ下書きが自動で実額にする**
- 実額は内訳の欄を持てないので、**材料代も総額に含める**（下書きが注記を出す）
- パネル・加算基礎・バンパ・内板骨格・付加塗装・追加項目・材料代のどれかがあるときは実額にできない（指数のまま。下書きが注記）
- 「参考」は `"input_type": "参考"`。計算は指数と同じで `InputTypeName` だけが変わる
- **実額を指定したときは内訳があっても実額にする**（2026-09-20）。`"input_type": "実額"` と書かれていれば、下書きがパネル・塗装行・バンパ・加算基礎・ブース・追加項目・材料代の割合を畳み、**総額 ＝ 塗装工賃計 ＋ 追加項目 ＋ 材料代** の 1 つにする（`draft_estimate._force_actual_paint`）。内板骨格塗装・ボデーシーリングは塗装計とは別の欄なので畳まない（残っていれば今までどおり一括計上）。検算（`run_case`）は実額のとき塗装工賃計・材料代を個別に見ず、**塗装計（材料込）**で突き合わせる。アプリ（neo-estimate）はコグニの NEO を作るとき必ずこれを指定する（ベタ打ちは別経路なので対象外）

## 3. 明細 → 外板パネルの自動連動（コグニが自動で塗装パネルを選ぶ仕組み）

**コグニは明細に入れた部品から塗装パネルを自動で起こす**。実案件 1,643 行のうち **1,565 行（95%）が自動連動**（`AddedFrom 0`）で、そのうち **1,560 行は明細に同じ部品コード・同じ修理方法の行がある**（食い違い 5 行は枝番・再検索の残り）。

| 明細の行 | 塗装パネル | `DisposalCode` | 塗装面積 |
|---|---|---|---|
| 取替（20.DB にあるパネル） | 自動で 1 枚 | 0 取替 | 面積の区分なし（`PaintingArea -1`） |
| 板金 | 自動で 1 枚 | 6 板金（`DisposalName` は「修理」） | 1/2 が最頻（272 行）、1/3（128）、1/1（93） |
| 修理 | 自動で 1 枚 | 2 修理 | 1/3 が最頻（105 行）、1/2（25）、1/1（16） |
| 20.DB に無い部位（ルーフサイド・テールゲート…） | **行追加**（手入力の塗装行） | 9 | なし（判断規則 10-20） |
| 高機能塗装（耐スリ傷・スクラッチ）をパネル単位で足した行 | 行追加 | 7（`DisposalName` が「耐スリ傷」「ｽｸﾗｯﾁ」） | なし |

- **`AddedFrom 0`（自動連動）の行は、明細にその部品コード・修理方法が無いとコグニが塗装ページを開いた時点で消える**（実機 W90 で塗装計が 176,560 → 142,610 に落ちた）。生成器はこの違反を `ValueError` で止める
- 手で足したパネル（`AddedFrom 1`）は工賃印 `*` が付き、明細に無くても残る
- 指数を標準以外にするときは `Manual=1, WageByManual='#'`（`Manual 0` のままだとコグニが標準へ戻す）
- **塗装面積（1/1・1/2・1/3）とパネル面積（dm²）は別物**（判断規則 10-12）。見積書の `20dm²` は塗装面積の目安で、`PanelArea` は 20.DB の値
- 工場が塗装を一式でしか出していない見積を**パネル別に組み直す**のが `paint.auto_panels`（判断規則 10-15）。明細の取替・板金・修理行から同じ規則でパネルを起こし、差は材料代で埋める

## 4. 塗り数値（指数）はどこから来るか

| 項目 | ADDATA の表 | 備考 |
|---|---|---|
| パネルの塗り数値 | `<car>.CHM` の表（塗料 × 塗膜 × 単体塗/複数塗 × 面積） | パネル 1 枚なら単体塗、2 枚以上は複数塗。高機能塗装の加算は `TimeStandardHF`（面積 33 → 0.6 = floor10(0.3 + 0.01 × 面積)） |
| 加算基礎数値 | `COM/T_KEI_3.DB`（車形 × 塗料 × 塗膜 × 高機能 × 枚数） | パネルが 1 枚でもあれば入る。手入力の塗装行は枚数に数えない |
| ブース加算 | `COM/BOOTH.DB` | 高機能塗装のときは 0 |
| バンパ | `<car>23.DB`（水性は `93.DB`）8 列 = [新品一色, 新品二色, 外傷大一色, 外傷大二色, 外傷小一色, 外傷小二色, 変形一色, 変形二色] | 絞模様ありは +0.4 |
| バンパ加算基礎 | `COM/BAN.DB`（車形 × 塗膜クラス） | **パネルが 0 枚でバンパだけ塗るとき**だけ。パネルを 1 枚でも足すと消えて加算基礎数値になる |
| 内板骨格塗装 | `COM/NAIKOKUA.DB`（車形 × No 01〜09） | §6 |
| 付加塗装 | `COM/fukaetc.DB`（8 行）・`COM/2TONE.DB`（水性は `W2TONE.DB`） | 枚数 → 指数の表 |

## 5. 塗装条件（塗料・塗膜・高機能）

- `Paint` 1 速乾 / 3 ２Ｋ / 4 水性（水性は CHM の水性ページ・93.DB・W2TONE.DB を使う）
- `Coat` 1 ソリッド / 2 メタリック / 3 ２コートパール / 4 ３コートパール（`66.DB` の先頭桁）
- `HFPainting` 0 しない / 1 フッ素 / 2 耐スリ傷 / 3 スクラッチ
- **塗膜は見積書の印字（塗装条件）を優先**。カラーコードから引ける塗膜と違っても印字どおり書く（判断規則の「塗装」）
- 3コートパールと2コートパールは加算基礎が違う（アルファード 4.1 vs 3.4）ので読み間違えない

## 6. 内板骨格塗装（ラジエータサポート・ピラー・リヤフロア）

**実案件 700 本中 279 本（40%）が使っている**。コグニの塗装画面「内板骨格」タブで、位置ごとに区分を選ぶだけの欄（金額は `COM/NAIKOKUA.DB` の車形別の指数 × レバーレート）。

| 欄（reading のキー） | コグニの表示 | 区分 | NAIKOKUA の No | 実案件の指数の例 |
|---|---|---|---|---|
| `engine_room`（エンジンルーム） | ラジエータサポート / フロントフェンダエプロン | 1 = ラジエータサポート両側新品または修正 / 2 = ＋Fフェンダエプロン片側 / 3 = ＋両側 | 01 / 02 / 03 | 1.1〜1.3（1）/ 1.0〜1.8（2）/ 1.9〜2.6（3） |
| `front_pillar`（フロントピラー） | 片側新品 / 両側新品 | 1 / 2 | 04 / 05 | 0.6〜1.0 / 1.2〜1.8 |
| `center_pillar`（センタピラー） | 片側新品 / 両側新品 | 1 / 2 | 06 / 07 | 0.9〜1.2 / 2.0 |
| `rear_floor`（リヤフロア） | １台小修正 / １台大修正 | 1 / 2 | 08 / 09 | 0.9〜1.0 / 1.4〜1.7 |

- **印字は 2 行に分かれることがある**: 「ラジエータサポート 両側新品」＋「フロントフェンダエプロン 片側新品または修正」= エンジンルームの区分 2。下書きは同じ欄の区分を**大きい方に寄せて 1 つにまとめる**
- **転記はそのまま塗装行（`paint.lines`）に写せばよい**（2026-09-20〜）。下書きが名前から内板骨格タブに振り分ける。区分の語（片側新品 / 両側新品 / １台小修正 / １台大修正）が無いピラー・フロアの行は**外板パネル**として扱う（「フロントピラー 修理 1/2」を内板骨格にしない）
- 直接書くなら `"frame": {"engine_room": {"option": 2, "index": 1.5, "wage": 13130}}`
- **内板骨格塗装は塗装工賃計に入り、材料代の対象**（材料の欄 `er_Material*` は -1 で、区分ごとの材料代は持たない）
- 内板骨格**修正**（内骨画面の FramePlan / Frame。基本修正作業＋ランク A/B/C）とは別物。あちらは `estimate.frame`

## 7. 材料代（割合と端数処理）

**材料代 = 塗装工賃計 × 材料代割合**。割合はコグニの塗装条件の欄（`MaterialRate`。実案件 700 本すべて**整数 %**）。

- 実案件の割合の分布: 28%（138 本）/ 23%（100）/ 26%（67）/ 21%（35）/ 25%（32）/ 31%（23）/ 27%（19）…（0% = 材料代なしが 95 本）
- **端数処理は工場ごとに違う**（コグニの環境設定。NEO には残らない）。実案件 366 本で確かめた内訳:
  - **10 円四捨五入**で説明できる 332 本（既定。コグニ実機 2026-09-05 で確認）
  - **10 円切り上げ**でしか説明できない 22 本
  - **1 円単位**の工場もある（JPN タクシー 127,466 × 16% = 20,394.56 → 印字 20,395）
  - どれでも説明できない 5 本（材料代を手で直した案件）
- **転記は材料代の金額をそのまま写す**。下書きが「割合（整数 %）× 端数処理」を割り出し、ぴったり戻るなら**費用割合モード**で渡す（`MaterialTotalbyManual` が空 = コグニが計算した形）。戻らなければ額を手入力（`*`）で渡す
- 割合の印字がある見積は、その割合で戻るかを先に確かめる（戻らなければ実際の割合を割り出し、印字の割合と 0.5% 以上離れていたら採らない）
- 割り出した端数処理が既定（10 円四捨五入）以外のときは `paint.material_round`（例 `{"unit": 10, "mode": "切り上げ"}`）が estimate に入り、**確認箇所シートの 要確認**になる
- 見積書に材料代も割合も無いときは、**SHOUCHIKU ガイドライン表の「6500〜」列**の既定値を使う（判断規則 10-19）
- 材料の列だけに金額のある行（ショートパーツ・写真代を材料の列に刷る工場）は材料代に足す（判断規則 10-30）。この材料代は「塗装工賃計 × 割合」ではないので割合モードにしない

## 9. reading.json への書き方（転記の手引き）

```jsonc
"paint": {
  "paint": "2K", "coat": "3コートパール", "hf": "耐スリ傷",     // 塗装条件の印字どおり
  "total": 74800,            // 印字の「塗装工賃計」（内板骨格塗装を含み、追加項目を含まない）
  "material": 19450,         // 印字の「塗装材料代（計）」。割合は下書きが割り出す
  "material_rate": 26,       // 割合が印字されていれば書く（無ければ書かない）
  "lines": [                 // 塗装明細の行を印字の順に、名前をそのまま
    {"name": "右 ﾌﾛﾝﾄﾌｪﾝﾀﾞﾊﾟﾈﾙ 修正 1/3", "index": 2.5, "wage": 21250},
    {"name": "ﾗｼﾞｴｰﾀｻﾎﾟｰﾄ 両側新品", "index": 1.5, "wage": 13130},   // → 内板骨格タブへ
    {"name": "ﾌﾛﾝﾄﾌｪﾝﾀﾞｴﾌﾟﾛﾝ 片側新品または修正"},                    // → 同じ欄の区分を 2 に
    {"name": "加算基礎数値", "index": 4.1, "wage": 34850},
    {"name": "ﾌﾛﾝﾄﾊﾞﾝﾊﾟｰ 取替", "index": 2.2, "wage": 18700},
    {"name": "ﾌﾞｰｽ", "index": 0.3, "wage": 2550},
    {"name": "ｱﾝﾀﾞｰｺｰﾄ", "wage": 5000}                              // → 追加項目（材料代の対象外）
  ]
}
```

**下書きが行の名前から振り分ける先**

| 印字の名前 | 行き先 |
|---|---|
| 加算基礎数値 | `base` |
| ブース | `booth` |
| ラジエータサポート / フェンダエプロン / Fピラー・Cピラー（片側新品・両側新品）/ フロア（１台小修正・１台大修正） | `frame`（内板骨格タブ） |
| 2コートソリッド（ルーフ・ルーフ以外 N 枚） | `two_coat_solid` |
| 防錆ワックス・ワックス | `wax` |
| ボデーシーリング（m 数） | `sealing` |
| ○○バンパ 新品/変形修正/外傷修正小/外傷修正大（一色・二色） | `bumper_front` / `bumper_rear` |
| 「部位名 + 取替/修理 + 1/1・1/2・1/3」で 20.DB に当たる | `panels`（外板パネル） |
| 20.DB に当たらない部位名 | `panels` の**手入力の塗装行**（行追加） |
| 工程の名前（アンダーコート・内板調色・チッピング・ヒンジ・ホイルハウス・インナー・下地・材/剤/費） | `other`（追加項目。材料代の対象外） |

**一式しか印字が無いとき**は `lines` を書かずに `total` だけ（＋あれば `material`）→ 下書きが**実額**で書く。パネル別に組み直したいときだけ `"auto_panels": true`。

## 10. よくある落とし穴

| 症状 | 原因 | 直し方 |
|---|---|---|
| 塗装計が印字と合わない | 内板骨格塗装・付加塗装を数えていない | 印字の塗装工賃計は内板骨格塗装を**含む**・追加項目を**含まない**（§1） |
