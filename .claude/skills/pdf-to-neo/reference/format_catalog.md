# 工場見積の書式カタログと写像規則

届く見積書は大きく 5 系統。分類の決め手は「部品コード列」「指数列」「区分の語彙」「装備注記」。どの書式でも最終形は同じ estimate.json なので、違いは **読み取り方と `index_policy`** だけ。

| 系統 | 見分け方 | 実案件 | index_policy | 読み取りの要点 |
|---|---|---|---|---|
| A. コグニ印刷 | 4 桁の部品コード列がある。名称が 20 文字半角カナ（`右Frﾌｴﾝﾀﾞ`）。「作業計/塗装計/材料計」 | サンプル NBOX / エスクァイア / C-HR（工場 A（案件 C01）） | auto | code をそのまま入れる。指数は標準と一致するので `#` はほぼ付かない。ページ小計は `pages`（reading）か `pages/page_N.json` の `subtotal` に（`totals.pageN` は書式 A の判定ヒントにしか使われない） |
| B. 他システム印刷（指数あり・コードなし） | 指数・技術料・数量・部品金額・部品品番・素材の列。【ブロック名】見出し。金額の無い装備注記行 | 工場 B（アルファード） | auto | 品番で照合（今回 22/23 が品番一致）。装備注記行は明細に入れず装備判断に使う。指数はコグニ標準と一致する行と違う行が混在（違う行は `#`） |
| C. 日産系 FAX（区分語彙が違う） | 区分が「取替/部品/脱着/修理」。工賃が円未満まで計上（8,610×1.3=11,193） | 案件 N-ONE（日産系ディーラー） | manual | 「部品」→取替、工賃は **コグニ丸め（10 円四捨五入）** に直して入れる。合計が −8 円等ずれるので `totals.neo_total`+`tolerance` を理由付きで |
| D. ディーラー概算（品番・金額のみ） | 指数列なし。塗装は「塗装一式」。輸入車が多い | 案件 C03 ボルボ V40 | auto | コグニ非収録車なら `vehicle.generic=true`（Z10 等）・全行 `manual`。塗装は `paint.total` 一括 |
| E. 板金工場 FAX（多ページ・混在） | 概算見積 4〜5 ページ、保留・リサイクル・内板骨格・費用 5 種 | 案件 C02 シエンタ（板金工場） | auto | `reserve` / `recycle` / `frame` / `expenses(taxfree)` を使う。ページごとの小計で読み取りを検算 |

判定に迷ったら B として読み、指数が全行コグニ標準と一致すれば A と同じ扱い、全行違えば C（manual）にする。

## 系統別の細則

### A. コグニ印刷

- 部品コードは 4 桁（`0010`）。枝番付き（`0010-02`）は code に 4 桁だけ入れ、名称で区別。reading.json では `rows[].code` に写す（script がそのまま ref にする）
- 右端の印: `$` = 暫定指数（ADDATA の Provisional。生成器が 11.DB から自動で付ける）、`#` = 手入力指数、`*` = 手入力工賃/手入力金額。コード欄が空の行は手入力行（`manual: true`）
- 工場のコグニが **工賃 100 円丸め**に設定されていると 0.25×11,000 = 2,800 のように印字される。生成器は 10 円丸めなので、その行は `*`（手入力工賃）になる（合計は一致。オデッセイ 2026-09-07）
- 塗装費用・材料・諸費用が「塗装」「費用」の見出し無しで明細に並び、コード欄が空なら、工場は塗装/費用画面を使わず手入力行で入れている。同じように `manual` 行で写す（`paint` / `expenses` は空）。部品計・工賃計が印字と一致する（オデッセイ: 部品計 718,420 = 明細 651,520 + 塗装材料 61,900 + 産廃 5,000）。**修理方法欄が空欄ならそのまま空**（コグニは DisposalCode −1 で保存。実機 2026-09-08）
- 印の位置: 価格を手入力した行は、価格欄ではなく工賃欄の右端に `*` が出る。工賃欄に金額が無く `*` だけなら価格の印、金額の後ろの `*` は工賃の印、`**` は両方（実機 2026-09-08 exp_manual）
- 同じ部品コードが 脱着 と 板金 の 2 行に分かれて印字されることがある（2700 スライドドア）。そのまま 2 行で写す
- 「保留」「リサイクル」「コメント」行はコグニの印字規則どおり（NEO 仕様 §10）。`reserve` / `recycle` / `comment`
- 塗装明細（外板パネル・バンパ・加算基礎・ブース・付加塗装）は項目名がコグニと同じなので、そのまま `paint` に写す
- **コグニ帳票の実物（2026-09-08 実機出力 見積り1/見積り2/見積り1(塗装明細)）**: 帳票 PDF には文字層がある（FAX 化されていなければ pypdf で読める）。列は `ｺｰﾄﾞ 修理項目／部品名称 修理方法／部品番号（／指数） 部品価格(円) 工賃(円)`、見積り2 は品番の後ろに指数が続く（`67510-TY0-309ZZ3.00` のように詰まる）。印: 価格を手入力した行は工賃欄の右端に `*`、工賃手入力 `25,000*`、指数手入力 `24,000#`、手入力行は `61,900 *`、価格と工賃の両方なら `3,000**`
- 塗装明細付き帳票では【塗装明細】節に `塗装費用計 / 塗装工賃計 / 塗装材料代計 / 塗料 / 塗膜`、パネル行 `2700左 ｽﾗｲﾄﾞﾄﾞｱﾊﾟﾈﾙ 取替 92d㎡ 12,800`、`加算基礎数値 ( 2.90) 23,200`、`フロント樹脂バンパ 新品 一色 13,600`、`塗装材料代 34,320`、`材料代割合 55.0%` が並ぶ。**ページ小計・小計の工賃列は 明細工賃 + 塗装工賃計 + 材料代**（151,120 = 54,400 + 62,400 + 34,320）。reading では `paint.lines` にパネル行・加算基礎・バンパ行を、`paint.material` / `material_rate` / `total`（塗装工賃計）を書く。材料代が 塗装工賃計 × 割合 の一括四捨五入と一致すれば draft が費用割合モードにする
- 見積書 PDF に `塗装費用(工場見積) 0 *` の行が出ることがある（一括計上で作った NEO を開いて塗装画面を使ったときの名残）。明細ではないので写さない

### B. 他システム印刷（工場 B 型）

- 名称は工場システムの正式名（`ﾌﾛﾝﾄﾊﾞﾝﾊﾟ ｶﾊﾞｰ`）。コグニ名（`Fﾊﾞﾝﾊﾟｶﾊﾞ-`）とは違うが、品番一致で ref が決まるので名称は補助
- ブロック見出し（【フロントバンパー】【右 フロントフェンダー】）は、同じ品番が複数ブロックにある部品（`52161-16010` バンパピース、`90467-07214` クリップ）の ref を決める文脈。見出しの直後の行から順に items を並べる（生成器は直前行の ref のブロックを文脈にする）
- 装備注記行（金額なし・「インテリジェントクリアランスソナー」等）: その直前の部品の 11.DB 条件を示す。装備レターの判断材料にする（judgment_rules.md「装備」）
- 「区分」語彙: 取替 / 脱着 / 鈑金 / 塗装。鈑金行の名称に `(5dm²)` があれば損傷面積
- 塗装ブロック: 「塗料 2K」「塗膜 3コートパール」「高機能塗装 耐スリ傷」の見出し行、「右 フロントフェンダパネル 修正 1/3」= panels、「加算基礎数値」= base、「フロントバンパー 取替」= bumper_front 新品。数量列 0.50 は材料代割合ではなく **各行の材料代割合の表示**（0.55 なら 55%）。材料代は行ごと四捨五入
- 「諸費用」ブロック: どの合計に入るかで kind を決める（ショートパーツ・写真代 → 部品計 → parts、コーティング → 諸費用計 → wage）
- 「素材」列の `*`: 手入力品目（ADDATA に無い）。`manual: true`

### C. 日産系 FAX（非コグニ書式）

- `index_policy: "manual"` にする（指数を全部 `#` にしないとコグニの再評価で工賃が消える）
- 工賃は円未満を切らずに計上されているので、`wage` にはコグニ丸め値を入れ、`totals.total` は FAX の値、`totals.neo_total` にコグニ丸めの期待合計、`tolerance` に差額を書く
- Honda 純正品番はハイフン無し（`71101T4GN00ZF`）でも 11.DB の品番と照合できる
- ぼかし塗装など工賃の無い塗装行はコメント行

### D. ディーラー概算（品番・金額のみ）

- 指数が無いので工賃は見積書の値を `wage` に。取替/脱着行で工賃欄が空なら `wage` を省略して標準指数に任せる（コグニ収録車のとき）
- 塗装一式は `paint.total` のみ。材料代が別立てなら `material`
- 輸入車: 車名・エンジン・カラーは手入力。塗装指数なし（塗装条件タブのみ）

### E. 板金工場 FAX（多ページ）

- ページ小計は `pages/page_N.json` の `subtotal` に入れ、`reading_pages.py validate` でページごとに検算
- 「保留」と書かれた行は `reserve: true`（金額は合計に入らない）
- 内板骨格（基本修正作業 + ラジエータサポート等の部位）は `frame`
- 費用に「非課税」があれば `taxfree: true`

### F. 技術料だけの工場書式（指数の列が無い。工場 R / ディーラー BP センター（トヨタ系） / Ducati。2026-09-09）

- 見出し: 「作業内容・使用部品 / 個数 / 部品金額 / 技術料」または「品名 / 部品番号 / 数 / 価格 / 工賃 / 小計」。
  **指数の列が無い**のが目印。部位の見出し（（部位:リヤバンパ）等）がある書式と、平坦に並ぶ書式の両方がある
- 明細は実額で入れる（`wage` だけ書き `index` は書かない → コグニは `*` の手入力工賃）。
  **`manual: true` にはしない**。名称照合で ref を決める（判断規則 10-7）
- レバーレートは速報の「工賃単価」が最優先。無ければ `scripts/guess_labor_rate.py` で逆算（判断規則 10-6）
- 金額が税込で印字されることがある（下の G）。合計欄の消費税と課税小計の関係で見分ける
- 部位の見出し行（金額の無い「左 クオータパネル修理」等）は明細にしない

### G. 金額が税込で印字された見積書（二輪ディーラー（Ducati 系） / ディーラー BP センター（トヨタ系）。2026-09-09 に 2 件連続）

- 見出し: 「消費税10％対象(込) ¥…」「整備代金お見積金額（税込）」「消費税の記載のないのは、10％課税の商品です」
- **各行の金額まで税込**。そのまま写すと課税小計が 1.1 倍になる。各行を (100+税率)/100 で割って税抜にする
- `totals` は **金額項目をすべて**税抜（`tax` / `total` と制御キーは除く）。対象の正確な一覧は判断規則 10-4
- 10% 以外なら `totals.tax_rate` に税率を書く。**ただしこれは見分けに使うだけで、生成器の消費税と
  `Setting.TaxRate` は 10% 固定** —— 8% など 10% 以外の案件は **NEO を作らずに報告する**（judgment_rules 10-4）

## 読み取り時の共通チェック

1. レバーレート = 工賃 ÷ 指数 が全行で同じか（違う行は読み取りミスか手入力工賃）
2. 数量 × 単価 = 部品金額 か（見積書は数量分の金額を印字する書式と単価を印字する書式がある。`price` は **数量分**）
3. 各ブロックの小計・ページ小計・作業計・部品計・塗装計・材料計・諸費用計・消費税・御見積額が全部つながるか
3-2. **合計欄が税込で刷られていないか**: 「課税小計 × 税率 ≠ 消費税」なのに「課税小計 × 税率 ÷ (100+税率) = 消費税」なら税込印字（系統 G）。
     **税率が 10% 以外（8% など）なら、そこで止めて報告する** —— 生成器の消費税と `Setting.TaxRate` は 10% 固定なので
     合計が正しく出ない（judgment_rules 10-4）
4. 消費税の丸め: 既定は四捨五入（切り捨て/切り上げの工場設定は draft が合計欄から自動判定して `tax_round` に入れ、生成器も同じ単位で計算する）（748,081 × 0.1 = 74,808.1 → 74,808）。コグニの消費税設定は **1 円単位の 3 択だけ**なので、それで説明できない工場側の丸め（10 円単位など）は `neo_total` / `tolerance` / `tolerance_reason` の 3 点で残す（判断規則 10-5）
