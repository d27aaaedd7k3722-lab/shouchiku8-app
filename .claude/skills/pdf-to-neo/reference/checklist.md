# 納品前チェックリスト

全部 ✅ になるまで「完了」と言わない。1 つでも ❌ なら報告に「未完了の項目と理由」を書く。

## 読み取り

- [ ] 工場見積 PDF と車検証を両方読んだ（無い方は報告に明記）
- [ ] レバーレートを 2 行以上で逆算して一致した
- [ ] 明細の数量 × 単価 = 金額 を全行確認した
- [ ] ブロック小計・ページ小計・作業計・部品計・塗装計・材料計・諸費用計・消費税・御見積額が電卓で全部つながった
- [ ] 装備注記行・保留行・リサイクル行・コメント行を明細と区別した

## ページ単位の転記（pages/ → reading_pages.py）

- [ ] 2 ページ以上はページ単位で写した（`pages/header.json` + `page_N.json`）。各ページの `rows_printed`・ページ小計・印の数を先に書いた
- [ ] OCR 先読み（`ocr_prefill.py`）を使った行は画像で名称・品番・数値を確認し、comment の「OCR未確認」を全部消した
- [ ] `reading_pages.py validate` が全ページ合格、`merge` が FAIL なし（WARN は理由が言える）
- [ ] `reading_check`（make_neo の最初）が FAIL なし。`--skip-check` を使ったなら理由を報告に書いた

## reading.json（→ draft_estimate.py が estimate.json を作る）

- [ ] JSON は Write ツールか Python で書いた（heredoc に `\` を入れていない）。`json.load` が通る
- [ ] `vehicle` に型式・車台番号・型式指定・類別・初度登録・カラーがある（無い項目は理由を `source` に）
- [ ] `blocks` は見積書のブロック見出しと行の並びどおり。名称・区分語・品番は印字のまま、金額は数量分
- [ ] 注記行（金額なし）は `note`、素材欄 `*` や社外品は `manual: true`
- [ ] `paint.lines` は塗装行を印字のまま（修正 1/n、加算基礎数値、バンパの方式、ボデーシーリングの長さ m）
- [ ] 塗装が「一式」しか無い見積書は `paint.auto_panels: true` を検討した（10-15）。
      使ったなら `_draft_notes` で起こしたパネルと材料代の割合を見て、常識的か確かめた
- [ ] 塗装行の `dm²` は**塗装面積**。パネル面積（20.DB）とは別物なので `area` に書かない（10-12）
- [ ] 生成後の塗装パネルの**面積が見積書の dm² と合っている**（20.DB はボディごとに別行を持つ。10-17）。
      ★『ボディ NN 用の行を選べなかった』が出た行は、見積書の指数を `paint.panels[].index` に書く
- [ ] `_draft_notes` の「追加項目（paint.other）にした」「手入力の塗装行にした」を見る。部位の名前が追加項目に、工程の名前が手入力の塗装行に入っていない（判断規則 10-20）
- [ ] `_draft_notes` の「追加項目（paint.other）にした」に **専用項目**（ボデーシーリング・加算基礎数値・ブース・防錆ワックス・バンパ）が混ざっていない
      （落ちると塗装工賃計と材料代が狂う。10-13）。内板調色などの追加項目や、
      「シーリング**材**料費」「シーリング**材**」「ボデーシーリング**剤**」のような材料側の行が paint.other に入るのは正しい
- [ ] `expenses[].in` にその費用が入っている合計欄の名前
- [ ] 費用の `name` は見積書の印字どおり（**全角なら全角**）。既定行に載るかは語による（10-11。
      漢字・英字のキーワードは載る／カナは ショートパーツ・アライメント・エーミング・コーティング だけ載る）。
      既定行に載せたい費用があるなら生成後に `Expense` の行番号か実機の費用画面で確かめる（載らなくても金額・合計は同じ）
- [ ] `totals` は見積書の合計欄そのまま。**ただし税込印字（10-4）の案件は例外** —
      部品計・工賃計・塗装・材料・費用・課税小計を税抜に直し、`tax` と `total` は印字どおりに書く
- [ ] `_draft_notes`（名称照合・左右分割・板金ランク・装備・paint.other・manual）を全部読んで納得した
- [ ] `_draft_notes` の「左右が食い違う」「前後が食い違う」が出ていない（出ていたら印字の部品コードか名称の写し間違い。合計は合うので検算では見つからない）
- [ ] 脱着・板金など**品番の出ない行の名称に左右が入っている**（左右のある部品なら「左Fr…」。10-10）
- [ ] 「… の行に部品代 … 円がある」が出ていない（部品代が付くのは取替の行と手入力行だけ）
- [ ] draft / 生成器が明確なエラーで止まった項目（数量 0 以下・未知の修理方法・未知の flags・20.DB に無い塗装パネル・負のレバーレート）は reading を直して解消した（握りつぶさない）

## 税と丸め（2026-09-09 追加）

- [ ] 合計欄で「課税小計 × 税率 = 消費税」が成り立つ。**成り立たないときは 10-4 のもう一方の式**
      「課税小計 × r ÷ (100+r) = 消費税」を確かめる。**前者が不一致で後者が一致なら税込印字**（系統 G）。
      どちらでもない差は 消費税の丸め（`tax_round`）・非課税費用・工場側の丸めを疑う
- [ ] 税込印字だったら、明細・塗装（詳細キーも）・費用・小計（`pages["N"]` と `blocks[].subtotal`）・
      `totals` の金額項目を **(100+r)/100 で割って税抜**にした。対象の正確な一覧は 10-4（`tax` / `total` と制御キーは割らない）
- [ ] 税率が 10% 以外（8% など）なら **NEO を作らずに報告した**（生成器の消費税と `Setting.TaxRate` は 10% 固定で、
      合計が正しく出ない。10-4）
- [ ] 10% 以外の見積は `totals.tax_rate` を書いた
- [ ] 合計差を残すときは `neo_total`・`tolerance`・`tolerance_reason` の 3 点が揃っている
- [ ] 合計を合わせるために明細の金額を動かしていない
      （例外は 10-14 の協定案件だけ。損保が「○○の工賃で調整」と指定した行の指数を動かすのは指示どおりの作業で、
      その旨と動かした前後の値を報告に書く。指示のない行を勝手に動かすのは禁止）
